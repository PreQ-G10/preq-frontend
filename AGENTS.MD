#Programming rules for this project

- **Representative names** - Don't use letter names, make the names of the variables descriprive for their purpose.
- **Apply duplicated code** - DRY principle (Don't Repeat Yourself). If a definition already exists in another file, use it. Do not duplicate common logic.
- **Cohesion** - If a function becomes too long, split it into smaller functions (divide and conquer). Keep functions short and focused on a single task.
- **Atomic Design Pattern** - This project organizes UI components following the Atomic Design methodology, which structures components into hierarchical levels of increasing complexity.
